# DzSetUnitID 探索操作说明

测试只使用原生步兵 hfoo、牧师 hmpr；没有接入 Xlimon。
单测入口已切到 DzSetUnitIDExplore_Test.j，使用 VERSION_UNITTEST 空地图。
通过编辑器任务「🥭启动:单元测试-vjassc」重新启动地图，看到 `[DzSetID] v1 已加载` 后输入命令。

## 最简单的第一轮

输入一次 `-all`，不用继续输入，约67秒顺序运行 s1、s2、s3、s4。
发生失败断言时会在本项结束后停止自动队列，并保留单位。请把日志给我分析。
类型ID没有变也可能存在模型等变化，不能仅凭失败提示推断API完全无效。

左右是对照，中间是实验单位：

- 左：原始步兵 A。
- 中：从步兵开始，调用 DzSetUnitID 的对象。
- 右：直接 CreateUnit 创建的牧师 B。

不要操纵左右对照单位。自动阶段不要操纵中间单位，以免污染移动/属性观测。
测试不会在修改类型后补设模型、属性、技能、显示或动画，也不会自动解除暂停。
右侧牧师创建时关闭自动治疗；实验单位如果替换后自行获得自动治疗，可能出现随后生命/魔法变化，因此以 RAW_AFTER_SET_ID 的即时值判断参数变化。

| 命令 | 时间 | 实验 |
| --- | --- | --- |
| s1 | 8秒 | 2秒改牧师；立即、0.1秒后、1秒后记录；4秒时向下移动；8秒检查并结束 |
| s2 | 40秒 | 每2秒切换一次类型，A→B→A，共20次；逐次记录，失败则结束 |
| s3 | 5秒 | 设置生命123、最大魔法333/当前77、基础攻击1234、护甲33、移速150、红色1.5倍、UserData24680，添加狂战士并施放，设置20秒冷却与暂停；再改牧师 |
| s4 | 5秒 | 活体改牧师后，由左侧步兵以脚本伤害致死，检查原单位死亡/受伤监听与玩家死亡监听 |
| s5 | 8秒 | 活体改类型 → 死亡 → DzReviveUnit |
| s6 | 8秒 | 死亡 → 尸体上改类型 → DzReviveUnit |
| s7 | 8秒 | 死亡 → DzReviveUnit → 活体改类型 |
| s8 | 手动 | 创建对照和右下角无敌靶，便于观察攻击、弹道、头像、技能按钮和碰撞 |

第二轮分别运行 s5、s6、s7，每项等 END 后再输入下一项。
尸体上改类型的行为未知，s6不纳入-all；如果发生中断或崩溃，保留日志并单独重开测试其他路线。
如果改类型本身已将尸体恢复为存活，日志会记录 REVIVE_SKIPPED，不再对活单位追加复活调用。

## 手动观察

输入 s8 后：

- `-b`：中间改牧师；`-a`：改回步兵。
- `-move`：尝试向下移动；也可自己下达移动命令，观察碰撞。
- `-attack`：攻击右下无敌靶，观察近战/远程、弹道、攻击距离和节奏。靶无敌，因此这里不验证伤害量。
- `-heal`：将左侧步兵生命设为100，再令中间单位施放治疗；不补加技能或魔法，故失败也有观测意义。
- `-kill` / `-revive`：中间单位死亡/复活，复活传入实际生命120、魔法30。
- `-status`：保存三只单位当前快照。
- `-stop`：取消自动队列、停止计时器并清理本组单位/专属触发器。
- `-help`：显示说明。

手动命令也可在单项 END 后使用；自动测试执行中会拒绝修改操作。
观察模型、大头像、技能按钮是否正确，不能只看 GetUnitTypeId 或名称。
s3设置的颜色、缩放是否保留需目视判断，日志没有假装用getter测量它们。

## 发回日志

日志前缀为 `[DzSetID]`，run区分每次重跑，mode对应s编号。
项目日志位于游戏工作目录的 `War3Lib\日志\`。请发送当前会话完整log，并说明外观/操作异常。

- BASELINE：三单位初始对照。
- SET_ID_BEGIN / SET_ID_RETURNED：标记API是否返回。
- RAW_AFTER_SET_ID / RAW_AFTER_REVIVE：调用刚返回的原始状态。
- NEXT_TICK / ONE_SECOND_LATER：延迟变化。
- CUSTOM_BEFORE_CHANGE：确认状态残留实验的前置条件。
- DEATH / PLAYER_DEATH / DAMAGE：不在类型切换时重新注册的监听结果。
- FINAL / END：各组最终状态和失败数。

属性差异属于探索结果，不要求实验单位必然等同全新牧师。通过检查也不证明所有属性已重置、性能有改善或多人同步安全。
本次未测试已RemoveUnit对象、非法ID、英雄/建筑/飞行类型转换；后续按结果决定扩展。

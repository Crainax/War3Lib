# 启动产物与清理

War3Lib GUI 启动器只保留 `Output/UnitTestMap_slk.w3x` 一份成品，全量或增量成功后覆盖。
不再为测试入口路径的哈希或 Lua 引擎创建长期地图目录。打包工作区复用
`Output/launcher/work/UnitTestMap`；增量缓存与状态使用 `engines/current`。

`Output/launcher/current-map.txt` 记录引擎、测试入口和版本。老地图或增量启动必须匹配此身份；
切换入口/引擎后先全量构建。开始替换地图前使清单失效，失败后不得把半成品作为可启动地图。
启动器用 `.build.lock` 串行化固定输出的构建与清理。原始 `UnitTestMap` 和当前 `UnitTest.h` 不因清理而删除或改写。

自动测试在进入 A/B 队列之前，将地图冻结到池 `snapshots/<唯一标识>/map.w3x`。
复制期间禁止源文件写入；排队期间覆盖原成品不改变已提交任务。分配环境后再复制到该环境的
`Maps/Test`。源码适配器仍使用原项目路径，并检查地图哈希；需要源码的项目继续持有自己的构建锁。

队列超时或启动前失败清理本任务快照；游戏结束后，只有 `cleanup.json` 确认归属清理成功，
才删除本局游戏地图及快照。地图身份不符或清理失败则保留诊断现场，不扩大删除范围。
会话日志、断言、OOS 与清理结果保留，地图副本不作为历史归档。

安全清理先运行 `pwsh -NoProfile -File script/CleanupWar3Output.ps1` 查看清单，明确执行才加 `-Apply`。
它只处理列出的旧启动目录和实验二进制；检查构建锁、进程/队列引用、文件占用、Git 跟踪和链接。
未知游戏归属时推迟删除。`KnownManualMap/Pid/CreationTicks` 只用于用户确认的人工局，保护该图所在目录，不能猜测填写。

保留当前成品、源码、总结、测试日志、复用工具依赖及仍在开发的实验目录。
旧文档中的 `Output` 路径是当时的本地验收产物，不承诺永久保留；历史结论不等于当前重新测试通过。

排队快照隔离和成功/超时清理。人工与池游戏同时运行仍须单独实机验证，不从离线检查推断。

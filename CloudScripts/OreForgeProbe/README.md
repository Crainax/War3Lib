# 独立原矿打造测试 OreForgeProbe

本测试不接入 Xlimon、不写其普通存档、不调用平台随机只读存档。
测试客户端：`Jass/learn/OreForgeProbe_Test.j`；云脚本入口：本目录 `main.lua`。

## 模型与范围

- 平台**数量型**道具 `OFPOre` 是累计获得原矿。云端调用 `MsGetPlayerItem(slot, "OFPOre")`，不接受客户端数量。
- **不会调用 `MsConsumeItem`**。商城数量保持不变；云端脚本存档的累计消耗递增，余额＝平台数量－累计消耗。
- 四种配方：0/1/2/3 条指定属性，价格由云端固定为 **1/3/15/50**。
- 七种属性是 **1～39 的测试编号**，不重复；锁定属性保证存在。未连接真实 ItemData、物品或 UI。
- 实际七个编号、配方、锁定列表、请求 ID、序号和累计消耗在同一玩家脚本存档中保存。
- 字段 `war3lib_ore_forge_probe_v1`；保留整份脚本存档中其他字段，不覆盖 MlsProbe 的计数。
- 请求 ID 随石头持久保存。同 ID 同配方返回 `REPLAY`，不保存、不扣费、不再次随机；锁定顺序不同仍视为同一配方。同 ID 换配方或锁定集合拒绝。
- 最多 25 颗，无删除、重置、增矿或任意保存接口。这是固定测试套件，不是正式洗炼功能。
- 初次生成采用云端运行时 `math.random`，不接收客户端种子、不在部署脚本中固定 seed。**尚未验证 MLS 随机初始化、跨房间随机质量或不可预测性。**
- 单房间每个玩家有在途保护；**没有实现/证明同账号跨房间的互斥与新鲜读档**，不能直接作为正式经济系统部署。
- 保存返回非零或异常后不发放属性、不自动重试，该槽位本次运行暂停；重开读取后只能用原 ID 恢复。返回0按现有 MlsProbe 契约处理，真实平台持久化仍须跨局确认。

## 两局验收（同一账号、同一测试地图、槽位0）

每条命令等回包后再发下一条。地图不会自动扣矿。

第一局：

| 命令 | 操作 | 预期 |
|---|---|---|
| `s1` | 读平台原矿、云端累计消耗及背包 | `STATUS acquired\|spent\|balance\|count=69\|0\|69\|0` |
| `s2` | F1，全随机 | CREATED，消耗1，余额68，1颗 |
| `s3` | F2，锁属性1 | CREATED，累计消耗4，余额65，2颗 |
| `s4` | F3，锁属性1、2 | CREATED，累计消耗19，余额50，3颗 |
| `s5` | F4，锁属性1、2、3 | CREATED，累计消耗69，余额0，4颗 |
| `s6` | 重发F4，锁定顺序改成3、1、2 | REPLAY，仍消耗69/4颗，属性与F4完全相同 |
| `s7` | F4改成锁两条配方 | REQUEST_CONFLICT；随后自动读回，消耗不变 |
| `s8` | 新请求但锁定列表1、1 | BAD_LOCKS；随后自动读回，消耗不变 |
| `s9` | 零余额新建F5 | NO_ORE；随后自动读回，消耗不变 |
| `s10` | 核验四条固定记录 | 检查全部断言，累计69、4颗，并打印四条STONE |

保存第一局日志后退出重开，**不要清档、不要改测试道具数量**。

第二局：

1. `s1`：应为 `69|69|0|4`，四条 `STONE` 的请求编号、序号、配方和七个属性与第一局一致。
2. `s10`：固定四颗、累计69的断言通过。
3. `s6`：跨局重试F4，必须 `REPLAY`，同一颗、累计69、余额0。
4. 可再输入 `s2`～`s5`：四条都应 `REPLAY`，不会再消费。这些命令是固定请求，不是每次新造。
5. `s9`：依然 NO_ORE。

需要把**两局完整日志和对应云脚本日志**留存。日志通常在魔兽目录 `War3Lib/日志/`；搜索 `[OreForgeProbe]`。`VERIFY FINISHED` 只是检查结束提示，须同时确认没有断言失败。

如果第一局已出现F1～F4，不要把重放误认作新生成成功。可使用全新测试账号重复完整流程；本脚本不提供删档快捷命令。

额外零材料验证：另一个从未跑过的测试账号，平台OFPOre为0，进入槽位0，`s1`后直接`s9`。应余额0/背包0并拒绝创建，跨局仍为空。

## 故障和限制

- `SAVE_UNCERTAIN_RESTART` / `OUTCOME_UNKNOWN_RESTART` / TIMEOUT：不要换新请求ID“补一次”；重开后`s1`检查。如果原请求已存，重发应REPLAY；若未存，可以原ID重新提交。
- 云端代码在返回结果前尝试保存整份状态，不把未保存的属性发给客户端；仍需验证线上返回值、回包丢失和持久化语义。
- `SOURCE_BELOW_SPENT`：平台原矿总数低于已用量，可能是配置调整或异常，测试拒绝继续，不自动归零或覆盖存档。
- 正常断线重开与模拟存储故障是不同验证。本次离线覆盖“保存失败”和“已经保存却返回错误”，但没有制造真实平台故障。
- 目前没有完成云脚本跨房间抢锁/CAS，不能以此声明双开可安全同时消费。平台正式接入前需独立验证。
- 25颗不删除，因此所有成功请求凭证都保留；正式业务若删除石头，去重凭证不能跟着删除。
